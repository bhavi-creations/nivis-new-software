LATEST SIMPLIFIED QUOTATION FLOW
create-quotation.php now displays only customer selection/search and product,
quantity, price, configured tax and total, with one Save quotation button.
The saved list exposes View and Convert to Invoice. Conversion is a single click
and supports saved drafts directly without a separate acceptance step, while
retaining transaction locks, document snapshots and duplicate-conversion checks.
It redirects to the invoice list and shows a success message. Converted invoices
are drafts until issued. New simple quotations use today's date, 15-day validity,
zero discount and the configured company terms; GST uses the saved customer state.
The earlier advanced quotation-form/status UI described below is superseded.
The direct-invoice form is unchanged. Added simple-quotation.php and
assets/js/simple-quotation.js; the HTTP suite covers saved-draft conversion.

DATABASE AND SETUP
The actual local schema was inspected. Existing Customers, Addresses, Categories,
Products, Tax Rates, HSN Mappings, Quotations, Invoice Items, Payments, Users,
Sequences, Audit Logs and Company Settings are reused. No business records were
deleted and no production tables were recreated.

The additive migration was already run against this local project database:
  C:\xampp\php\php.exe database\migrate_billing.php
Run the same command after deploying these files to another installation.
It can be run repeatedly. It adds missing optional product/customer/GST fields,
document party/detail snapshots, additional-charge totals, cancellation reasons,
and company document defaults. It requires ALTER permission. Normal API access
also checks for missing columns, consistent with the existing project convention.
Do not run setup.php --demo against an existing business database.

No new PDF dependency needs installation. The application reuses the existing
html2pdf.js 0.10.1 CDN dependency. If unavailable, the page explains the failure;
Print > Save as PDF remains available through the browser. No server PDF engine
was installed. Enable backgrounds and turn off browser headers/footers when printing.

ACCESS
No users/login were configured in the inspected application. A login page now
uses the existing users table and password_hash/password_verify. With zero users,
loopback-only XAMPP access works. Remote requests require sign-in. Once a user is
created, local requests require sign-in as well. Create your own admin credentials:
  C:\xampp\php\php.exe database\create_admin.php
The command prompts for name/email/password. It does not create sample credentials.
Admin and manager can write; staff is read-only. Sign out is available in the sidebar.
PHP session.save_path must be writable by the PHP process. Use HTTPS remotely.
CSRF tokens protect API writes and sign-in/sign-out. Browser mutation request keys
prevent repeat processing within the same session; the last 100 successful keyed
requests are retained. Conversion additionally has a transaction lock and unique
quotation reference, independent of session state. Number sequences are atomic.
The CLI is a trusted administrative context and does not require browser tokens.
Apache denies direct access to config/database/tests folders; equivalent rules
are needed on other web servers. Application login does not protect publicly
served product-image URLs; product images are not document attachments.

IMPLEMENTED BEHAVIOR
- Tax: add/edit/view, activate/deactivate, safe removal from future selection,
  optional HSN/SAC mappings, effective-from date, configured inclusive/exclusive
  pricing, and selection by tax-rate ID on the product edit screen.
- Products: existing-customer dropdown and typed search, saved customer linkage,
  original photo/category/quantity/price workflow preserved.
- Quotations: customer contact/address preview, multiple products, SKU/unit/stock
  hints, configurable charges with explicit classification/rate, tax split, terms,
  draft/sent/accepted/rejected/expired status paths, draft copies, date filters,
  customer/status/search filters and ten-record pagination. The existing database
  value 'approved' is retained for compatibility and displayed as Accepted.
- Invoices: direct creation or accepted-quotation conversion, direct draft line
  editing, draft due-date/notes editing, issuing, partial/full payments and notes,
  payment history, outstanding balances, date/status/customer filters, pagination.
  Converted draft line items retain the accepted quotation's financial snapshot.
- Unpaid issued invoices can be cancelled with a reason. Their number, values and
  audit record remain. Paid invoices cannot be cancelled through this shortcut.
- Documents snapshot parties, financial lines, classifications, descriptions,
  GST treatment, terms and charges. Conversion copies the saved quotation values.
  Later master-data changes do not rewrite these snapshots. No inventory is deducted.
- Print: standalone A4 view without sidebar/navigation in print, actual saved
  parties, existing logo, lines, totals, amount in words, configured terms/bank
  instructions/signatory name, payment balances, and PDF/print actions.
- All important totals are calculated server-side; submitted grand totals are
  ignored. Amounts use DECIMAL storage, line-level paise rounding, three-decimal
  quantities, two-decimal prices/discount percentages and two-decimal payments.
  Round-off is shown as zero; no undisclosed rupee-rounding adjustment is applied.

12. Open A4 views for short and long documents. Print and download PDF; verify logo,

LIMITS / ITEMS NOT CLAIMED COMPLETE
- No connected browser was available. A4 HTML and escaping were tested over HTTP,
  but visual rendering, actual PDF download, long-table pagination and interactive
  keyboard/responsive behavior have not been verified in a browser.
- This is an ordinary domestic-goods workflow using the project's existing eight
  supported states. Supplier state comes from Company Settings; saved shipping
  state defaults the place of supply, which must be reviewed for each transaction.
  Export/SEZ, bill-to/ship-to special cases, services place-of-supply rules, reverse
  charge, cess, e-invoicing/IRN and e-way bills are not automated. No GST rates are
  asserted as legally applicable; rate/HSN choice remains business configuration.
  Primary references reviewed:
  https://taxinformation.cbic.gov.in/content-page/explore-act/1000616/1000001
  https://cbic-gst.gov.in/gst-invoice-rules.html
- A credit-note/refund workflow for paid issued invoices is not implemented.
  Cancellation without payments is implemented and protected instead.
- Historical quotations created before snapshot support have no recoverable
  original customer/business snapshot. The print view says when details were not
  captured. Legacy conversion uses available master details; it cannot reconstruct
  a historical address. Existing issued invoice snapshots remain intact.
- Duplicate/draft copy uses current product tax configuration on the new save;
  review copied values before sending. Inactive/deleted products must be replaced.
- No user-management screen or password-recovery/email delivery was added. The
  existing users table and CLI account setup are used; sending a quotation is a
  status change, not an email transmission.
- List pagination is client-side. Large datasets would benefit from server paging.
