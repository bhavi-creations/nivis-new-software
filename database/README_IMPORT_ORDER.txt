Important:
1. Demo frontend JS values are NOT connected to database by these scripts.
2. Do NOT trust client-side totals/status. PHP should recalculate, validate, authorize.
3. Tax rates, HSN mapping and state/place-of-supply must be configured according to current law, not guessed.
4. Issue invoice numbers in a database transaction with a locked sequence row; do not calculate MAX(number)+1.
5. Conversion transaction: lock quotation FOR UPDATE, require approved and not converted, insert invoice + snapshot items, update quotation to converted, write status history/audit, COMMIT. The unique invoices.quotation_id key prevents duplicates.
6. Once issued, invoices/items should be immutable at application and database permission level. Use appropriate cancellation/credit-note workflows.
7. Before recording a payment/refund, lock invoice/payment and check against outstanding/refundable amount; do not accept overpayments or over-refunds accidentally.
8. Views provide reporting queries. Period-filtered payment reports should filter payment_date, not just invoice issue_date.
9. Store passwords only as strong salted hashes generated by server code (PHP password_hash); never plaintext.
10. Additional statutory invoicing/e-invoicing/e-waybill fields and rules depend on applicability; consult a tax professional before production.
